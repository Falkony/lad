# Лад — руководство для работы с проектом

Локальное однопользовательское приложение для личных финансов и дел. Интерфейс на русском,
валюта RUB. Стек: Nuxt 4, Vue 3, TypeScript, Nuxt UI, Tailwind CSS 4, Nitro, Drizzle ORM,
PGlite / PostgreSQL, Zod, decimal.js, Papa Parse, Vitest. Рендеринг клиентский (`ssr: false`).

## Команды

Нужен Node.js 22.12+ согласно README; зависимости устанавливаются через npm и `package-lock.json`.

| Команда                                          | Назначение                                                     |
| ------------------------------------------------ | -------------------------------------------------------------- |
| `npm ci`                                         | Установка зависимостей; `postinstall` выполняет `nuxt prepare` |
| `npm run dev`                                    | Разработка на `http://127.0.0.1:3000`                          |
| `npm run typecheck`                              | Проверка TypeScript и Vue                                      |
| `npm test`                                       | Все тесты Vitest, включая интеграционные с PGlite              |
| `npm test -- tests/money.test.ts`                | Пример запуска отдельного файла тестов                         |
| `npm run build`                                  | Production-сборка в `.output/`                                 |
| `npm run preview`                                | Запуск готовой сборки на loopback через `scripts/preview.mjs`  |
| `npm run format:check`                           | Проверка форматирования Prettier                               |
| `npm exec --offline -- prettier --write <файлы>` | Форматирование только изменённых файлов                        |

Для изменений кода выполни относящиеся к ним тесты, затем перед завершением задачи —
`npm run typecheck`, `npm test`, `npm run build`, `npm run format:check`.
Для изменений только документации достаточно проверить ссылки, команды и форматирование
изменённых Markdown-файлов. Сообщай о проверках, которые не удалось выполнить, и их причинах.
`npm run format` форматирует весь репозиторий; для локальной правки предпочитай конкретные файлы.

## Правила, которые нужно сохранять

- Деньги в DTO — строки в копейках, в БД — `numeric(16,0)`. Расчёты выполняются через `bigint`
  и decimal.js; не вводи floating-point арифметику для изменения денег.
- Факт, план и цели различаются: будущие планы и накопления, указанные в целях, сами по себе
  не меняют остатки счетов. Перевод между своими счетами сохраняет общую сумму.
- Изменения выполняются через `executeCommand` внутри транзакции с блокировкой `workspace_guard`
  и повышением ревизии. Сохраняй проверки устаревших форм и идемпотентность подтверждения дат.
- Каждая успешная команда завершает ту же транзакцию через `finishCommand()`: данные, ревизия
  и запись `command_history` фиксируются вместе. Не записывай журнал после commit и не обходи его
  в новых ветвях команд. Просмотр истории загружай страницами, не добавляй весь журнал в обычный Workspace.
- Копии версии 8 включают каталог, пояс, историю и графики через `readWorkspace(true)`; версии 1–7 совместимы (до версии 5 — без журнала). Reset очищает прежнюю историю, restore заменяет её из копии; оба действия
  записываются после замены с новой ревизией и требуют предварительную автокопию.
- Удаление операции мягкое. Архивный счёт сохраняет историю и деньги. Исходный счёт импорта
  (`importAccountId`) нужен для дедупликации даже после редактирования и удаления операции.
- График долга использует единую модель планов с `source: 'obligation'`; платёж записывается
  одной операцией. Не создавай вторую независимую модель графиков или расходов.
- Изменение БД требует новой версии SQL-миграции и синхронного изменения `server/db/schema.ts`.
  `drizzle-kit push` не является механизмом миграции этого проекта.
- Без `DATABASE_URL` реальные данные лежат в `.data/lad`. Одна папка PGlite — один процесс.
  Для экспериментов используй отдельный `LAD_DATA_DIR`; не используй пользовательскую БД в тестах.
- Автокопии сохраняются при запуске, каждые 10 успешных команд и перед reset/restore, отдельно от БД
  (по умолчанию `.data/backups`, 20 файлов; настройки `LAD_BACKUP_DIR`, `LAD_BACKUP_EVERY`, `LAD_BACKUP_KEEP`).
  Командная очередь включает предварительную копию и транзакцию; не обходи её при новых изменениях.
  Публикуй только проверенный полный файл, удаляй старые копии после новой. Ошибка копирования
  не должна выдавать уже закоммиченную команду за неуспешную; замена данных без предварительной копии запрещена.
- Приложение без авторизации: сохраняй loopback и проверки local-only / same-origin.
- Для новых стилей используй смысловые переменные `theme.css`; проверяй светлую и тёмную темы.
  Вспомогательные цвета обеих тем находятся в `theme-tokens.css`.

- Категории хранятся по ID с внешними ключами; имена служат отображению и совместимости.
- «Сегодня» вычисляется в часовом поясе пространства из settings, на сервере и клиенте.

## Обновление документации — часть задачи

- При изменении архитектуры, API, формата данных, команд, окружения, финансовых правил или
  ограничений обновляй соответствующий документ **в той же задаче, что и код**.
- При переносе файлов или изменении точек входа обновляй карту и ссылки в этом `AGENTS.md`.
  Здесь храни краткие устойчивые правила, подробности — в `docs/knowledge/`.
- Пользовательские возможности и запуск отражай в README; выполненные этапы и переносы задач —
  в roadmap. Не выдавай запланированную возможность за реализованную.
- Фиксируй значимые решения с причиной и ссылками на исходники или тесты. Не копируй код,
  полный перечень команд API и историю переписки; не сохраняй секреты и личные финансовые данные.
- Исправляй найденное противоречие с кодом в соответствующем разделе, не добавляй рядом вторую
  противоречащую инструкцию. Если поведение не подтверждено, явно помечай его как требующее проверки.

Начальная карта знаний сверена с исходниками 6 ноября 2026 года; эта дата не означает,
что перечисленные проверки выполнялись в последней задаче.
