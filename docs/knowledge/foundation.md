# Категории, часовой пояс и проверки

Этап 3.5, миграция 11, копии версии 6.

Каталог `categories` содержит постоянный UUID, уникальное имя и признак архива.
Операции (включая корзину), бюджеты, планы, их версии и отметки дат ссылаются на
`category_id` с внешним ключом и NOT NULL. Поле `category` остаётся отображаемым именем
для совместимости форм и расчётов. SQL-триггер переводит старые запросы с именем в ссылку;
при переименовании/объединении сервер согласованно обновляет отображаемые имена.
Денежные значения, импортные ключи и IDs финансовых записей миграция не меняет.

Команды каталога — `server/modules/categories.ts`: создание, переименование, архивирование,
объединение с проверкой ревизии предпросмотра. Совпадающие лимиты одного месяца при объединении
складываются; операции и их суммы сохраняются. Архив исключён из новых назначений; существующие
записи и редактирование их прочих полей доступны. Журнал команд сохраняет исходный запрос.
UI — `/settings`; `useCategories()` предоставляет актуальные варианты формам.

Часовой пояс IANA хранится в `settings.time_zone`, по умолчанию Europe/Moscow.
`shared/time-zone.ts` использует Intl.DateTimeFormat; `localDate()` делегирует вычисление дня
этому модулю. Подключение БД загружает настройку до проверки дат первого HTTP-запроса,
а клиент применяет её после чтения Workspace. Изменение, очистка и восстановление настройки
применяются только после успешной транзакции. Это текущая однопользовательская модель;
при нескольких пространствах контекст времени нужно изолировать по запросу.

Копии версии 6 включают каталог и пояс, проверяют ссылки. Версии 1–5 преобразуются:
по сохранённым именам создаются согласованные UUID, история версии 5 сохраняется.
Финансовые строки получают одинаковую ссылку для одного имени. Повреждённые ссылки нового
формата отклоняются. Reset удаляет каталог; стандартные варианты форм остаются доступны и
получают ID при первом использовании. Restore вставляет каталог до зависимых записей.

`.github/workflows/ci.yml`: Node 26, npm ci, типы, Vitest, Prettier и production build.
Локальная `.claude/` исключена из Git и форматирования; конфигурация пользователя не менялась.
GitHub Actions сможет подтвердить удалённый результат после публикации коммита.
Фикстуры старых БД используют `migrationThrough(version)`, чтобы новые миграции не попадали
в искусственно созданное старое состояние; новые шаги регистрируются в `migrationSteps`.

Проверки: `tests/foundation.test.ts` — сохранность миграции, стабильность ID при переименовании,
объединение лимитов и ссылок, архив, устаревшие предпросмотры, копии и границы дня UTC/IANA.

Результат: 140 тестов, typecheck, format:check и build прошли. Визуальная проверка страницы настроек не проведена: браузер отклонил доступ к localhost. Удалённый CI и перенос задач в GitHub Issues не подтверждены.
